# Glossary — Data-Pro-Skill Domain & Analytical Vocabulary

The canonical vocabulary for **Data-Pro-Skill**. Every command, agent, and script thinks with these **leading words** (_Leitworte_) to ensure **predictability**: taking the same rigorous analytical process on every run. Use these terms exactly; do not drift to synonyms.

**Bold terms** in any definition are themselves defined in this glossary.

---

## 1. Discovery & Data Grilling

How the agent uncovers the research objective, stakeholder priors, and data topology before running statistical models.

### Data Grilling
A relentless, structured interview (`/dps-grill` or `/dps-clarify`) conducted in **frontier** rounds before committing to an analytical pipeline. Adapts Matt Pocock's `grilling` and `domain-modeling` disciplines to survey and market research: the agent performs silent **fact reconnaissance** on the dataset first, then interviews the user on the open decisions in the **design tree**, updating the project's **schema mapping** and hypothesis log inline as answers land.

_Avoid_: generic Q&A, onboarding form, requirement gathering

### Fact Reconnaissance
The silent inspection of the dataset (`quant_analyzer.py --profile`, column headers, row count $N$, missingness rates, Likert scale bounds, multi-response groups, weight columns, and open-ended text fields) that the agent performs *before* asking the user a single question. Finding facts from the environment is the agent's job, never the user's.

_Avoid_: user data questionnaire, manual schema entry

### Design Tree
The dependency graph of analytical decisions explored during **Data Grilling**, spanning five canonical branches:
1. **Decision Destination**: What concrete Monday-morning action, budget allocation, or policy change rides on this report, and who is the target reader?
2. **Hypotheses & Priors**: What do stakeholders currently believe is happening, and what quantitative finding would falsify that prior?
3. **Analytical Spine**: Which variable is the primary dependent outcome (e.g., NPS, Churn, Overall Satisfaction, Spend), and which variables define the canonical **segments** (banners)?
4. **Weights & Governance**: Does the sample require **raking (IPF)** against universe targets or uniform weights (`weight = 1.0`), and what survey skip/branching rules apply?
5. **Deep Methodologies**: Which advanced modules (**Pure Sentiment Stack**, **Priority Matrix**, **Dual Clustering**, Factor Analysis/PCA, **TURF**, Qualitative Injection) are required to resolve the hypotheses?

_Avoid_: checklist, questionnaire template

### Frontier
Every decision in the **design tree** whose prerequisites are already settled — the questions the agent can ask *now* in a single round without guessing at upstream answers. Each round presents the entire current frontier with numbered questions (`❓ **Q1**`) grounded in concrete dataset facts and a recommended default (`➡️`) worded so `"yes"` accepts it.

_Avoid_: question queue, backlog

### Analytical Spine
The quantitative **manifesto** (`00_project_manifest.md` + `setup_manifest.json` + `setup_segments.csv`) generated by `/dps-setup`. It locks total sample size $N$, global margin of error, canonical **segments**, and baseline metrics as the single source of truth. No downstream command (`/dps-cross`, `/dps-execute`, `/dps-advanced`, `/dps-inject-open`, `/dps-export`) may contradict metrics established in the spine or invent standalone segments outside it.

_Avoid_: summary file, draft report, scratchpad

### Schema Mapping
The bidirectional dictionary (`column_mapping.json`) mapping clean, Pythonic `snake_case` variable identifiers (e.g., `satisfaction_overall_score`) to their exact original survey question text (e.g., `"14. De 0 a 10, qual sua satisfação geral com o evento?"`). Enforces `survey_governance.md`: code and statistical models operate exclusively on `snake_case` keys, while **Booktabs tables** and **Tufte HTML** reports render human-readable labels.

_Avoid_: raw column headers in code, unmapped variable codes

## 2. Statistical Governance & Bases

The non-negotiable mathematical rules enforced by the **Critic** via `constitution.md`.

### Data Constitution
The eight-article body of law (`constitution.md`) governing all outputs in Data-Pro-Skill:
- **Article 1**: Mandatory 95% CI Margin of Error (`±Y%, 95% CI`) on every sample percentage.
- **Article 2**: Statistical significance gate ($p < 0.05$) with exact test statistic, degrees of freedom, sample size $N$, and mandatory effect size.
- **Article 3**: Prohibition of prose fluff and enforcement of the **Deletion Test**.
- **Article 4**: Prohibition of percentages (`%`) in qualitative samples where segment $N < 30$ (raw counts `n of N` only, minimum 2 literal verbatims per theme).
- **Article 5**: Minimum sample size ($N \ge 30$ per group/cell) and normality verification for parametric tests, with automatic fallback to non-parametric equivalents.
- **Article 6**: Data Quality Gates — **Straight-Lining** detection (6a), percentage sum validation $100\% \pm 0.5\%$ (6b), and missingness reporting at $>10\%$ and $>20\%$ thresholds (6c).
- **Article 7**: Survey Governance — explicit weight handling (`weight` column), **Schema Mapping**, and **Branching Overlap** validation.
- **Article 8**: Tufte Print-Ready HTML Deliverable Standard — self-contained HTML with booktabs tables, margin notes, inline vector charts, and `@page` / **Print Frame** running headers and footers.

_Avoid_: best practices, style guidelines, optional suggestions

### Valid Base
The count of respondents ($n_{\text{valid}}$) who provided a non-null, substantive response to a specific question (excluding `NaN`, system missing, or skipped branch rows). Single-choice (`RU`) and scale relative frequencies are computed over the **Valid Base**, while always disclosing **Total Base** ($N_{\text{total}}$) when $n_{\text{valid}} < N_{\text{total}}$.

_Avoid_: ambiguous N, unlabelled denominator

### Total Base
The total sample size ($N_{\text{total}}$) of the survey or segment. Used as the denominator for Multiple-Response (`RM`) questions (where respondents can select multiple options and column sums legitimately exceed $100\%$) and for calculating variable missingness rates.

_Avoid_: row count

### Branching Overlap
The mathematical intersection size ($N_{A \cap B}$) of valid respondents between two survey variables $A$ and $B$ prior to cross-tabulation (`survey_branching_validation.md`). When $N_{A \cap B} = 0$ (a `0x0` contingency matrix), the variables sit on mutually exclusive skip-logic branches; the pipeline halts the cross and reports the structural survey branching rule rather than throwing a runtime error.

_Avoid_: empty table error, silent drop

### Raking (IPF)
Iterative Proportional Fitting (`scripts/weighting.py`) used to adjust disproportionate sample marginal distributions (e.g., Gender, Age, Region) until they converge on known population universe targets. When a survey is unweighted, an explicit `weight = 1.0` column is initialized (`explicit_weight_handling.md`) so every aggregation operator remains weight-aware.

_Avoid_: ad-hoc multipliers, unweighted assumption

### Straight-Lining
Responder inattention pattern on multi-item Likert batteries ($\ge 5$ items) where $\ge 80\%$ of consecutive responses from a single respondent are identical (`Article 6a`). The pipeline flags the straight-lining rate and computes a sensitivity delta: if excluding straight-liners shifts any headline metric by $> 2.0$ percentage points, both inclusive and exclusive figures are reported.

_Avoid_: speeders, flatliners

### Standardized Residual
In a contingency table cell $(i, j)$, the Pearson residual $z_{ij} = (O_{ij} - E_{ij}) / \sqrt{E_{ij}}$, where $O_{ij}$ is observed frequency and $E_{ij}$ is expected frequency under independence (`new_methodologies.md`). Cells with $|z_{ij}| \ge 1.96$ ($p < 0.05$) represent statistically significant local anomalies (positive attraction or negative rejection) that drive **Margin Note** insights.

_Avoid_: raw percentage difference, eyeball anomaly

## 3. Deep Survey Science

Advanced analytical methodologies in `references/analysis/` for isolating true sentiment, causal drivers, and natural audience segments.

### Pure Sentiment Stack
The two-stage bias-removal pipeline (`halo_removal.md`, `new_methodologies.md`, `science.md`) that strips individual rating inflation/deflation and general brand impression from multi-attribute rating batteries:
1. **Ipsative Centering**
2. **Halo Residual** extraction

_Avoid_: raw attribute means

### Ipsative Centering
Subtracting each respondent's personal mean rating ($\bar{X}_i$) across all rated attributes from their individual rating on attribute $j$ ($I_{ij} = X_{ij} - \bar{X}_i$). Isolates within-respondent relative preference, neutralizing "easy grader" vs. "harsh critic" scale usage bias.

_Avoid_: z-score standardization across columns

### Halo Residual
The residual $\varepsilon_{ij} = X_{ij} - \hat{X}_{ij}$ from regressing attribute $j$'s score against the respondent's personal mean or overall evaluation (`halo_removal.md`). Positive residuals indicate the attribute outperforms the respondent's general halo expectation; negative residuals expose hidden operational drags.

_Avoid_: simple difference from grand mean

### Priority Matrix
A strategic 2×2 quadrant model (`priority_matrix.md`) crossing **Derived Importance** (correlation or Random Forest/Regression driver weight with the primary outcome) against **Performance** (mean score or Top-2-Box), ranking every attribute by its **Priority Score**:
$$\text{Priority Score} = \text{Importance} \times (\text{Scale}_{\max} - \text{Performance})$$
Classifies attributes into four quadrants:
1. **Maximum Priority (Opportunity)**: High Importance, Low Performance — immediate investment.
2. **Maintenance (Core Strength)**: High Importance, High Performance — protect standard.
3. **Indifference (Low Priority)**: Low Importance, Low Performance — monitor only.
4. **Over-investment (Surplus)**: Low Importance, High Performance — reallocate resources.

_Avoid_: stated importance ranking, unweighed gap score

### Pain Curve
Non-linear threshold analysis (`science.md`, `priority_matrix.md`) plotting an attribute's rating against overall rejection, churn, or disapproval rate to identify the exact inflection score where dissatisfaction triggers defection (the "Hard Rejection" cliff).

_Avoid_: linear trendline assumption

### Dual Correlation
Side-by-side computation of **Pearson's $r$** (linear association on interval/ratio scales) and **Spearman's $\rho$** (rank-order monotonic association on ordinal/Likert scales) (`new_methodologies.md`). Divergences ($|\rho - r| > 0.10$) expose non-linear saturation or cliff effects.

_Avoid_: Pearson-only correlation on Likert data

### Dual Clustering
Running **K-Means** (exhaustive partitioning into $K$ actionable marketing personas, optimized via Silhouette score) alongside **DBSCAN** (density-based clustering that isolates noise/outlier respondents as cluster `-1` and uncovers tight natural sub-populations) or **Gower Distance Agglomerative Clustering** for mixed categorical + numeric variables (`new_methodologies.md`, `analytical_methodology_patterns.md`).

_Avoid_: forced K-Means without outlier diagnostics

### Expectation Residual
Segmentation of respondents based on the residual between their actual satisfaction/outcome $Y_i$ and the model-predicted satisfaction $\hat{Y}_i$ given their attribute ratings (`causal.md`):
- **Disappointed** ($Y_i \ll \hat{Y}_i$): Experiencing an unmeasured friction point not captured by standard attributes.
- **Aligned** ($Y_i \approx \hat{Y}_i$): Driven predictably by measured attributes.
- **Delighted** ($Y_i \gg \hat{Y}_i$): Experiencing organic brand/emotional goodwill beyond operational scores.

_Avoid_: raw satisfaction buckets

### TURF
Total Unduplicated Reach and Frequency (`scripts/turf_analysis.py`, `multivariate.md`). Combinatorial optimization that identifies the minimal subset of $k$ items (products, channels, features, events) maximizing unique respondent reach ($\ge 1$ item selected).

_Avoid_: simple top-N frequency picking (which suffers from audience cannibalization)

## 4. Agent Architecture & Tufte Output

How Data-Pro-Skill structures its execution engine and formats its deliverables.

### Invisible Agent Loop
The silent internal verification pipeline executed before any analytical command emits output (`references/agent-loop.md`):
1. **Statistician** (`agent-statistician.md`): Validates bases, weights, distributions, assumption checks, test selection, and effect sizes.
2. **Critic** (`agent-critic.md`): Audits against all 8 articles of the **Data Constitution**, blocking delivery on any violation.
3. **Anthropologist** (`agent-anthropologist.md`, active on `/dps-inject-open` and `/dps-mode:quali`): Extracts segment-anchored themes, literal verbatims, archetypes, and silence notes.
4. **Tufte Designer** (`agent-tufte-designer.md`): Synthesizes validated findings into high-density Tufte Markdown and **Print-Ready Tufte HTML**. The user sees *only* Stage 4.

_Avoid_: exposing raw intermediate agent chatter to the user

### Deep Module
A script or component (`scripts/*.py`) that hides substantial statistical and formatting complexity behind a small, deterministic CLI interface (`codebase-design`). Places the agent in the **pit of success**: calling one command enforces weighting, assumption checks, margin of error, and Tufte rendering automatically.

_Avoid_: shallow wrapper, ad-hoc one-off script

### Context Pointer
A compact reference in `SKILL.md` or `AGENTS.md` that names a disclosed reference file (`references/*.md` or `references/analysis/*.md`) and states the exact **branch** condition under which the agent must load it (`writing-for-agents`).

_Avoid_: dumping all reference prose into `SKILL.md` (**Sprawl**)

### Data-Ink Ratio
Edward Tufte's governing aesthetic principle: the proportion of a document's ink (or pixels/words) devoted to non-redundant display of data-information. Maximized by eliminating prose throat-clearing, chartjunk, 3D effects, heavy gridlines, and decorative chrome.

_Avoid_: decorative dashboards, wordy transitions

### Booktabs Table
Tufte table typography (`references/styles/tufte.css`): horizontal rules only at the top (`2px`), below the header (`1px`), and at the bottom (`2px`), with **zero vertical gridlines** and **zero zebra striping**. Every table is self-explanatory, carries its key finding in the section header or caption, includes an explicit `N` column, aligns numbers with `tabular-nums`, and reports `±MoE% (95% CI)`.

_Avoid_: boxed Excel grids, vertical borders, tables without N

### Margin Note
An interpretive callout (`> **Margin Note:**` / `> **Nota de Margem:**` in Markdown; `<aside class="margin-note">` floating in the 36% right column in Tufte HTML) placed immediately after a table or chart. Answers *"So what?"* in 1–3 sharp sentences: names the causal mechanism, business implication, statistical anomaly ($|z| > 2$), or supporting qualitative verbatim. Never repeats numbers already visible in the table.

_Avoid_: generic caption, table restatement

### Deletion Test
The mechanical prose audit from `constitution.md` Article 3: if a sentence can be removed without losing a numeric value, a named entity/segment, or a falsifiable analytical finding, it is prose fluff and must be deleted.

_Avoid_: throat-clearing openers ("It is important to note that...", "Based on the data provided...")

### Print Frame
The dual standard in `references/styles/tufte.css` and `scripts/tufte_html.py` that guarantees any **Tufte HTML** report (`final_report.html`) prints to PDF with publication-grade pagination, running headers, and running footers across all browsers and CSS Paged Media engines:
1. W3C `@page` margin boxes (`@top-left`, `@top-right`, `@bottom-left`, `@bottom-right`) with page counters and document metadata strings.
2. A repeating HTML `<table class="print-frame">` with `<thead>` and `<tfoot>` height spacers paired with `position: fixed` running header and footer bars in `@media print`, plus `break-inside: avoid` rules on tables, figures, and margin notes so content never collides with headers/footers or splits mid-table.

_Avoid_: external LaTeX/Quarto toolchains, unpaginated web dumps
